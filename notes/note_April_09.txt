** Parallel software
* Shared memory model
	- Generalise one program or procedure using a given mem to many procedures in the mem
	- These concurrent procedures are usually called processes or thread
	- The mem is shared memory: each process can read and write to it
	- Sfotware view: distributed mem mechanisms may be used to implement parallelism in the the hardware

	- Starting a process is called 'forking' and terminating them is called 'joining'

	- We often see a notion of process at OS level (UNIX)
		+ Characteristics
		+ Heavy weight
		+ LArge initialization, swapping overhead
	- Within a process, we often find light-weight threads
		

* Burden on software
	- In shared mem programs
		+ Start a single process and fork threads from the master process
		+ Threads can carry out tasks
	- In distributed mem programs
		+ Start multiple processes
		+ Processes carry out tasks

* SPMD
	- A SPMD programs consists of a single executable that can behave as if it were multiple different programs through the use of conditionals

*Writing parallel programs
	[1] Divide the work among processes/threads
	[2] Arranged for processes/threads to sync
	[3] Arrange for comms between processes/threads

* Nondeterminism
	- Race condition
	- Critical section
	- Mutually exclusive
	- Mutally exclusive lock (mutex, or simply lock)

* Comms and sync
	- Threads often need comms
	- Var in shared mem can be used for comms
	- We must ensure that only one thread updates the val (the value is called 'critical section')
	- Many machanisms exist for sync and mutual exclusion

* Monitor
	- Is a high level mechanism to manage critical sections
	- See slide 16 on week 6 for diagram

* OpenMP
	- API for shared mem parallel programming
	- MP = multiprocessing
	- Designed for systems in which each thread or process can potentially have access to all available mem
	- system is viewed as a collection of cpu, all of which have access to to main mem

* Pragmas
	- Special preprocessor instructions
	- Typically added to a system to allow behaviors that aren't part of the basic C specifications
	- Compilers that don't support pragmas ignore them

	- OpenMP is conceptually a fork but abstracted the many information needed to to provide in order to use for() operation
		+ So it's a high-level and easier to use fork()
* OpenMP pragmas
	- '# pragma omp parallel'
		+ Most basic parallel directive
		+ The number of threads that run the following structured block of code is determined by the run-time system

* Clause
	- Text that modifies a directive
	- The num_threads clause can be added to a parallel directive
	- Allow programmer to specify number of threads that should execute in the code block

* Parallel for
	- Forks a team of threads to execute the following structured block
	- However, the structured block following the parallel for directive must be a for loop
	- Furthermore, with the parallel for directive the system parallelizes the for loop by dividing the iterations of the loop
among the threads
	- Quick way to generate parallelism but the loop must satisfy certain constraints
		+ But the Open MP must know the amount of iterations and the constraints

[Note]
	- OpenMp does not check for dependencies in a loop. So if you want to calculate a fib number (if you want fib(6) then you need fib(5) adn fib(4))
	- A llop in which the results of one or more iterations depend on other iterations cannot, in general, be correctly parallelized by OpenMP
