**Q1: 
* Self-assumption:
- With the presented instruction, there could be limitations on communicating with nodes that are directly opposite of
a current node, you'll need to travel about p/2 nodes where p is the number of processors

* Tutor
- The ring topology is easy to design but quite slow for performance
	+ It is difficult for a node to communicate with another node opposite to it in a ring
- Every single processor sends values to the left (lesser node) but actually expects to receive from the left
	+ But the left never sent back any data
	+ One way to solve this is to make:
		~ Even nodes send to left
		~ odd node receive from right
		~ odd send left
		~ even recv right
	+ Either that or all nodes could execute
		~ Send left
		~ Recv right

[5]: Blocking means that send and recv operations will wait (like recv wait for a value)
- Non-blocking does not wait, if there is no msg pushed to queue before then the process might break
	+ Non-blocking is harder to design but has better performance and could avoid deadlocks
