[Msg blocking]
Blocking is used to preserve integrity when send

- Send is finished when msg buffer has been fully transferred to the MPI sys
- Receive is finished when msg arrived at destination and is available

- MPI also give 'non-blocking' operations

[Collective communication]

* Broadcast
- Master got some data and want to give it to the rest of the process group
- Use the collective operation 'broadcast'
	+ It puts the info at the same place at different rank on the system
	+ Can use 'send' and 'recv' but broadcast uses one conventional steps so more efficient
and simpler
- Want to bring processed data back to master
	+ Use the inverse of 'broadcast' -> 'Scatter'

=> When dealing with input, always use the master (process 0) -> It keep things neat and simple

*Example analysis
- Data would normally exist as a buffer for send and recv


[Collective vs Point to Point]

- All the processes in the communicator must call the same collective func
- The argument passed by each process to an MPI collective communication must be 'compatible'
	+ Even if a param is null, they still need to be specified


- P2P are matched on the basis of tags and communicators

- Collective communications don't use tags
- Collective is matched solely on the basis of the communicator and the order in which they are 
called


[Interconnection networks]
- Parallel processor has 2 major components
	+ Processor
	+ Interconnection network (IN)
- IN is important in all high-performance machines

[Shared memory interconnect]
- Bus interconnect
	+ A collection of parallel comm wires together with some hardware that controls access to
bus
	+ Comm wire are shared by the devices that are connected to it
	+ As number connected to bus increase, contention for use of bus increases and performance
decreases


-> Cross bar connection (figure 2.7 or part a slide 41) is the most efficient way to tackle this but
is also the most expensive way


[Fully connected network]
- EAch switch is directly connected to every other switch -> Impractical, especially for scaling

[Hypercube]
- Highly connected direct interconnect
- Built inductively:
	+ A one-dimensional hypercube is a fully connected sys with 2 processors
	+ A 2-dimen hypercube is built from 2 1-dimen hypercube by joining "corresponding"
switches
	+ Similarly a 3-dimen hypercube is built from 2 2-dimen hypercube
- Properties of d-dimen hypercube
- Latency grows with log(N)
- Wire cost also Nlog(N) as opposed to N for mesh



[Omega network]
- Use the bits of dest address to set the switch at each stage
	+ So for example, 0 is left and 1 is right. to look for 110, it will be right -> right -> left
	+ When enter the network, you can enter using the starting address's path
- One weakness of this is that it may create a hotspot that will create contention for traffic

* Latency: time it take from send -> recv
* Bandwidth: total rate of transfer that a path can tolerate
